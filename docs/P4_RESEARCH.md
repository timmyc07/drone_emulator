# P4 backend research — 2026-10-14

This is historical research from before the browser pivot. The active target is the local browser game described in [WEB_GAME.md](WEB_GAME.md). The desktop/Unreal implementation sequence below is suspended; it does not authorize new Unreal work, JSBSim installation or later-phase implementation. No browser backend extension is claimed from this research.

Read-only research was completed while P3 acceptance remained in progress. This is not an implementation or flight-validation claim. Do not advance past critical failed P3 gates.

The smallest next multirotor extension reuses the current RK4/motor/controllers and Eigen's rank-aware rectangular solve for symmetric six/eight upward rotors. The four-rotor constraint also exists in configuration validation, snapshots/reset/allocation, headless CSV and input replay, and Unreal's 28-column state playback. Update every boundary together and preserve quad behavior. Required checks include allocation rank, saturation, thrust/torque signs, hover, recovery and session round trips. [PX4's allocator](https://github.com/PX4/PX4-Autopilot/tree/main/src/modules/control_allocator) is an established BSD-licensed reference; using its algorithms does not establish a SITL connection.

For fixed-wing, investigate a separately built JSBSim shared library. The official [v1.3.2 release](https://github.com/JSBSim-Team/jsbsim/releases/tag/v1.3.2), commit prefix `14d2372`, includes rotor/propeller reset fixes. Current CMake source uses C++17; the older manual's C++98 claim is stale. A native Windows build is possible without WSL, but was not executed in this research. Verify the pinned build and bundled Expat notices before adoption.

Keep one authoritative backend. A JSBSim adapter would reuse `LoadModel`, `RunIC`, `Setdt`, `Run` and reset, converting its state to existing SI/ENU/FLU snapshots. Test feet/metres, NED/ENU, FRD/FLU, quaternion direction and geodetic origin explicitly. Do not run our integrator or ground clamp after JSBSim stepping. [Executive API](https://github.com/JSBSim-Team/jsbsim/blob/v1.3.2/src/FGFDMExec.h), [reference frames](https://jsbsim-team.github.io/jsbsim-reference-manual/user/concepts/frames-of-reference/) and [Project AirSim's integration](https://github.com/iamaisim/ProjectAirSim/blob/main/docs/physics/jsbsim.md) provide reusable references.

Licensing must be reviewed at library and aircraft-file level. The [Unreal EULA](https://www.unrealengine.com/eula/unreal) has a shared-library exception for LGPL; do not statically fold JSBSim into the Unreal module. Upstream aircraft examples have separate restrictions: [C172P](https://github.com/JSBSim-Team/jsbsim/blob/master/aircraft/c172p/c172p.xml) states that the model is not to be sold; the [AH-1S example](https://github.com/JSBSim-Team/jsbsim/blob/master/aircraft/ah1s/ah1s.xml) has GPL/alternative noncommercial share-alike terms and limited validation. Neither was selected or redistributed. Choose a suitably licensed, documented non-weaponized model before packaging.

Confidence exceeds the project's threshold for attempting an isolated pinned JSBSim build and implementing tested symmetric hexa/octocopter support. Actual adapter correctness, aircraft fidelity, helicopter envelope and VTOL transition/control remain unverified; VTOL confidence is below the implementation threshold. No JSBSim dependency, aircraft example or SITL was installed by this research.
